# Weekly Report Inputs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four inputs the weekly report will read, ahead of the report itself, so data builds up while the report is built: a gender on every Trainee, a parent phone for every child, a daily Check-in, and Quick tags that Trainers tap in the calendar roster sheet after a Slot.

**Architecture:** One expand-only migration adds three profile columns, one order column and three tables (Check-ins, Quick tags, Quick tag notes) with RLS on and no client policies. Pure rules (gender parsing, the parent phone prompt, Check-in and Quick tag validation and timing) live in small tested modules. Trainee writes go through server actions that check the signed-in Trainee and write with the service role; staff writes go through `verifyAdminOrTrainer()` plus the branch and Slot checks the roster already uses. Two new feature modules (`src/features/checkins/`, `src/features/quick-tags/`) and one small one (`src/features/parent-phone/`) hold the code; the existing profile, enrollment and roster code changes only where a field joins.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, Supabase Postgres, Tailwind CSS 4, shadcn/Radix, React Hook Form + Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-11-weekly-report-design.md`, sections "Quick tags", "Check-in", "Parent phone", "Gender" and "Data". This plan is step 1 of its "Order of work". Nothing here writes a report, calls a model or sends a message.

## Global Constraints

- Work on a branch `feat/weekly-report-inputs` cut from `main`. Commits use `feat(weekly-report): ...` (or `test(...)`, `refactor(...)`), ending with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Use `GRAPHIFY_SKIP_HOOK=1` for branch switches (the graphify post-checkout hook exits 1).
- All user-facing text in Hebrew; RTL; logical properties only (`ms-`/`me-`, `ps-`/`pe-`, `start`/`end`), never `left`/`right`. No emojis anywhere. No em dashes in copy.
- Immutable updates only: build new arrays and objects (`map`, `filter`, spread), never mutate.
- TypeScript strict, no `any`, no new `typedFrom` call sites: use the generated types.
- Every id from a client goes through `isValidUUID()` or `UUID_REGEX` (`src/lib/validations/common.ts`). Dates are Israel calendar days from `israelToday()` (`src/lib/utils/tasks.ts`) and `israelDateStr()` (`src/lib/utils/israel-time.ts`).
- The three new tables are read and written only by server code with `createAdminClient()`. Never import it into a client component.
- Tests cover pure functions only (project rule: no mock-based tests). Vitest, files in a sibling `__tests__/` folder. Write each test first and watch it fail.
- Files at most 400 lines where possible (800 hard cap); functions under 50 lines. `RosterSheet.tsx` is already 533 lines: add to it only the few lines Task 15 names.
- The migration is applied to production before the code deploys (expand only), then `npm run db:types` regenerates `src/types/database.generated.ts`. Never edit that file by hand. Confirm with the user before `supabase db push`.
- Domain words from the spec and `CONTEXT.md`: Trainee, Trainer, Slot, Roster, Quick tag (תגית), Check-in (צ'ק-אין). Never "שאלון" for the Check-in (that word belongs to the fixed forms).

## Review Focus

1. **A child types their own phone as the parent phone.** It must be refused with "זה המספר שלך. צריך את המספר של אחד ההורים", whatever spelling they type (`050...`, `+972...`). Pinned by `parentPhoneRefusal` "own phone in another spelling" (Task 6).
2. **A Trainee answers the Check-in twice in one day.** The second answer replaces the first, and the streak counts the day once (the streak trigger fires on insert only; the second save is an update). Pinned by the upsert in Task 10 and the trigger in Task 1.
3. **A Quick tag on someone who was not at the Slot**: a late cancel, a recorded removal, a free-text name, or a Called off Slot. Each is refused by the server, not only hidden in the sheet. Pinned by `tagTargetRefusal` and `tagWindowRefusal` (Task 12).
4. **Gender never overwritten.** The Arbox sync, `/join` and the signing page fill gender only when it is empty; only the staff user form can change a set value. Pinned by the fill rules in Tasks 3 and 5.
5. **A Check-in at 00:30 Israel time** belongs to the new Israel day, not the UTC day. The action takes the date from `israelToday()` on the server, never from the client.

```sql
ALTER TABLE public.profiles
  ADD COLUMN IF NOT EXISTS gender text
    CONSTRAINT profiles_gender_known CHECK (gender IN ('male', 'female')),
  ADD COLUMN IF NOT EXISTS guardian_not_needed boolean NOT NULL DEFAULT false,
  ADD COLUMN IF NOT EXISTS guardian_prompt_dismissed_at timestamptz;

COMMENT ON COLUMN public.profiles.gender IS
  'male or female: how Hebrew text addresses the Trainee. Filled when empty by /join, the signing page and the Arbox sync; changed only by staff.';
COMMENT ON COLUMN public.profiles.guardian_not_needed IS
  'The Trainee answered "אני מעל 18" on the dashboard: no parent phone is asked for.';
COMMENT ON COLUMN public.profiles.guardian_prompt_dismissed_at IS
  'Last "לא עכשיו" on the dashboard parent phone card; the card returns 7 days later.';

ALTER TABLE public.orders
  ADD COLUMN IF NOT EXISTS child_gender text
    CONSTRAINT orders_child_gender_known CHECK (child_gender IN ('male', 'female'));

COMMENT ON COLUMN public.orders.child_gender IS
  'The gender typed on /join; fulfillment copies it to the profile when the profile has none.';

CREATE TABLE IF NOT EXISTS public.trainee_checkins (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  trainee_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  checkin_date date NOT NULL,
  sleep_hours numeric(3,1) NOT NULL
    CONSTRAINT trainee_checkins_sleep_range CHECK (
      sleep_hours >= 3 AND sleep_hours <= 12 AND sleep_hours * 2 = floor(sleep_hours * 2)
    ),
  energy smallint NOT NULL CONSTRAINT trainee_checkins_energy_range CHECK (energy BETWEEN 1 AND 5),
  soreness boolean NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT trainee_checkins_one_per_day UNIQUE (trainee_id, checkin_date)
);

COMMENT ON TABLE public.trainee_checkins IS
  'A Trainee''s daily Check-in (sleep, energy, soreness), one per Israel day. Written by saveCheckinAction with the service role.';

CREATE TABLE IF NOT EXISTS public.slot_trainee_tags (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  slot_id uuid NOT NULL REFERENCES public.daily_schedule_slots(id) ON DELETE CASCADE,
  trainee_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  tag text NOT NULL CONSTRAINT slot_trainee_tags_known CHECK (tag IN (
    'effort', 'progress', 'focus', 'leadership', 'technique', 'personal_best', 'pain', 'behavior'
  )),
  created_by uuid REFERENCES public.profiles(id) ON DELETE SET NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT slot_trainee_tags_once UNIQUE (slot_id, trainee_id, tag)
);

COMMENT ON TABLE public.slot_trainee_tags IS
  'Quick tags a Trainer tapped for a Trainee after a Slot. Written by toggleQuickTagAction with the service role.';

CREATE TABLE IF NOT EXISTS public.slot_trainee_notes (
  slot_id uuid NOT NULL REFERENCES public.daily_schedule_slots(id) ON DELETE CASCADE,
  trainee_id uuid NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
  note text NOT NULL CONSTRAINT slot_trainee_notes_length CHECK (char_length(note) BETWEEN 1 AND 80),
  updated_by uuid REFERENCES public.profiles(id) ON DELETE SET NULL,
  updated_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (slot_id, trainee_id)
);

COMMENT ON TABLE public.slot_trainee_notes IS
  'The one short Quick tag note per Trainee per Slot. Written by saveQuickTagNoteAction with the service role.';

CREATE INDEX IF NOT EXISTS trainee_checkins_trainee_idx ON public.trainee_checkins (trainee_id, checkin_date DESC);
CREATE INDEX IF NOT EXISTS slot_trainee_tags_trainee_idx ON public.slot_trainee_tags (trainee_id);
CREATE INDEX IF NOT EXISTS slot_trainee_tags_created_by_idx ON public.slot_trainee_tags (created_by);
CREATE INDEX IF NOT EXISTS slot_trainee_notes_trainee_idx ON public.slot_trainee_notes (trainee_id);
CREATE INDEX IF NOT EXISTS slot_trainee_notes_updated_by_idx ON public.slot_trainee_notes (updated_by);

DROP TRIGGER IF EXISTS trainee_checkins_set_updated_at ON public.trainee_checkins;
CREATE TRIGGER trainee_checkins_set_updated_at
  BEFORE UPDATE ON public.trainee_checkins
  FOR EACH ROW EXECUTE FUNCTION public.set_row_updated_at();

-- A Check-in counts toward the streak like the forms do (006). Insert only: a
-- second answer the same day is an update and must not count twice.
CREATE OR REPLACE FUNCTION public.trigger_streak_checkin()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  PERFORM update_user_streak(NEW.trainee_id, NEW.created_at);
  RETURN NEW;
END;
$$;

DROP TRIGGER IF EXISTS streak_after_checkin_insert ON public.trainee_checkins;
CREATE TRIGGER streak_after_checkin_insert
  AFTER INSERT ON public.trainee_checkins
  FOR EACH ROW EXECUTE FUNCTION public.trigger_streak_checkin();

ALTER TABLE public.trainee_checkins ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.slot_trainee_tags ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.slot_trainee_notes ENABLE ROW LEVEL SECURITY;

REVOKE ALL ON public.trainee_checkins FROM anon, authenticated;
REVOKE ALL ON public.slot_trainee_tags FROM anon, authenticated;
REVOKE ALL ON public.slot_trainee_notes FROM anon, authenticated;
```
