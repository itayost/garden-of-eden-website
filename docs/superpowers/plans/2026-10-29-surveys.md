# Surveys Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admins and Branch managers write Surveys; Trainees in the Audience answer them once in a popup inside the app; staff read the results as an answer grid.

**Architecture:** A new feature module `src/features/surveys/` holds pure rules (state, permissions, audience, answers, offering, report) tested first, service-role loaders, and one-concern server actions. Seven new tables with RLS on and no client policies; two database functions make saving a draft and sending a Response atomic. The trainee popup mounts once in the trainee layout; staff pages live under `/admin/surveys`.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript strict, Supabase Postgres, Tailwind CSS 4, Radix (shadcn) Dialog, nuqs, papaparse, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-29-surveys-design.md` (read it with this plan; the approved mockups it cites are in `.impeccable/mockups/surveys/`, local and gitignored, with screenshots in `shots/`).

## Global Constraints

- Work on a branch `feat/surveys` cut from `main`. Commits use `feat(surveys): ...` (or `test(surveys)`, `refactor(surveys)`).
- All user-facing text in Hebrew; RTL; logical properties only (`start`/`end`, `ms-`/`me-`, `inset-inline-*`), never `left`/`right`.
- No emojis anywhere. Immutable updates only (no in-place mutation of arrays or objects).
- TypeScript strict, no `any`, no `typedFrom`: use the generated types from `src/types/database.generated.ts`.
- Domain words from the spec: Survey (סקר), Question, Response, Audience, Seen. Never "שאלון" for a Survey (that word belongs to the workout and nutrition forms).
- Limits, exactly: title 2 to 120 characters; intro at most 500; 1 to 20 Questions; Question text 2 to 300; choice Questions 2 to 10 options of 1 to 100 characters, no duplicates; rating 1 to 5; free-text answer 1 to 1000; rating end labels at most 40; results grid page size 20.
- Every id from a client goes through `isValidUUID()` (`src/lib/validations/common.ts`). Dates are Israel calendar days from `israelToday()` (`src/lib/utils/tasks.ts`).
- Survey tables are read and written only by server code with `createAdminClient()` (`src/lib/supabase/admin.ts`), behind `verifyAdminOrTrainer()` / `getBranchScopeAction()` (`src/lib/actions/shared/`) or the signed-in Trainee check.
- Tests cover pure functions only (project rule: no mock-based tests). Vitest, `import { describe, expect, test } from "vitest"`, files in a sibling `__tests__/` folder. Write each test first and watch it fail.
- Files at most 800 lines (aim for 200 to 400); functions under 50 lines.
- The migration is applied to production before the code that uses it deploys, then `npm run db:types` regenerates types. Never edit `database.generated.ts` by hand.
- Popup look (spec "The popup's look"): forest `#0A1F0A` sheet, raised `#142814`, brand lime `#CDEA68` (Tailwind `bg-forest`, `bg-forest-light`, `bg-brand-lime`); one-ring centre circle; neutral shadows only, never a lime glow; Bebas Neue (`var(--font-bebas)`) for rating numbers.

## Review Focus

1. A Trainee in two branches, seen by a Branch manager of only one: they appear once and count only under the manager's branch. Pinned by `buildSurveyReport` "a manager sees only their branch, a two-branch trainee once" (Task 6).
2. A Survey nobody has seen or answered yet: every percentage is 0 and the rating average is empty, never `NaN`. Pinned by "an untouched survey has zeros, not NaN" (Task 6).
3. An optional free-text answer of only spaces: treated as skipped, never stored as an empty answer; a required one is refused. Pinned in Task 4 ("spaces-only optional text is dropped", "spaces-only required text is refused").
4. Sending on the close date late at night (Israel time): still accepted; the next Israel day it is refused. Pinned by `surveyState` "still open on its close date" / "ended the day after" (Task 1); the action passes `israelToday()`.
5. A Survey edited (before its first Response) while a Trainee has the old popup open, or a double tap on "שליחה": the Trainee gets "הסקר עודכן בינתיים. סגרו אותו ופתחו שוב." or "כבר ענית על הסקר הזה", never a raw database error. Pinned by `submitErrorMessage` and the unknown-Question case of `answersProblem` (Task 4).

  - `SURVEY_LIMITS = { titleMin: 2, titleMax: 120, introMax: 500, questionsMax: 20, questionTextMin: 2, questionTextMax: 300, optionsMin: 2, optionsMax: 10, optionMax: 100, labelMax: 40, textAnswerMax: 1000, ratingMin: 1, ratingMax: 5 } as const`; `SURVEY_PAGE_SIZE = 20`

  - `interface ReportSeen { profileId: string; firstSeenAt: string }`

Rules (spec "Results" and "Audience"): the Audience counted is today's Audience plus anyone who answered; Seen is the Seen rows plus anyone who answered. A responder is placed by their snapshot branches, everyone else by current branches. `visibleBranchIds` and the branch and birth-year filters narrow Audience, Seen, answers and lists alike; search and segment narrow only the lists and the grid. Shares are of those who answered that Question, rounded to whole percent; the rating average is rounded to one decimal and null with no answers; percentages are 0, never `NaN`. Grid rows newest first; Seen-not-answered newest first seen; unseen by name (`localeCompare(b, "he")`); text answers newest first. `birthYears` lists the years in the visible Audience, newest first.
