# Player Summary Report -- Design Spec

## Overview

Automatic player summary report ("סיכום פעילות שחקן") generated by trainers/admins from the admin panel. Produces a professional PDF with player details, assessment data, performance charts, strengths/weaknesses from shift notes, social skills, and a trainer-written summary.

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Generation flow | Dedicated editor page (`/admin/reports/generate/[userId]`) | Full editing control before PDF download |
| Who generates | Trainers + admins | Both roles need this |
| Report persistence | Not saved -- data already in DB | Report is a computed view over existing data |
| Summary persistence | Saved to `trainee_summaries` table | Reusable across report generations |
| Attendance source | Arbox `entrance` report API | Real check-in data, linked via `arbox_user_id` |
| Strengths/weaknesses | Auto-pulled from shift reports by date range, editable | Configurable date range, trainer can edit before generating |
| Social skills | New category on end-of-shift form | Accumulates over time like other notes |
| Charts | Recharts (existing) + new RadarChart | Reused on both profile page and report |
| PDF generation | Client-side `@react-pdf/renderer` + chart snapshots via `html-to-image` | Extends existing pattern, no server dependency |
| Styling | Use `/ui-ux-pro-max` skill during implementation | Professional design for PDF and editor page |

### New table: `trainee_summaries`

```sql
CREATE TABLE trainee_summaries (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  author_id UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
  summary TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_trainee_summaries_user_id ON trainee_summaries(user_id);

-- Auto-update updated_at
CREATE TRIGGER set_trainee_summaries_updated_at
  BEFORE UPDATE ON trainee_summaries
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();

-- RLS
ALTER TABLE trainee_summaries ENABLE ROW LEVEL SECURITY;

-- Admins: full access
CREATE POLICY "admins_full_access_trainee_summaries"
  ON trainee_summaries FOR ALL
  USING (
    EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'admin')
  );

-- Trainers: can read all, insert/update own authored summaries
CREATE POLICY "trainers_select_trainee_summaries"
  ON trainee_summaries FOR SELECT
  USING (
    EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'trainer')
  );

CREATE POLICY "trainers_insert_trainee_summaries"
  ON trainee_summaries FOR INSERT
  WITH CHECK (
    auth.uid() = author_id
    AND EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'trainer')
  );

CREATE POLICY "trainers_update_trainee_summaries"
  ON trainee_summaries FOR UPDATE
  USING (
    auth.uid() = author_id
    AND EXISTS (SELECT 1 FROM profiles WHERE id = auth.uid() AND role = 'trainer')
  );
```

Latest summary per trainee (by `created_at DESC`) is used in report editor as default.

## Arbox Attendance Integration

### Arbox Reports API

The `entrance` report endpoint is documented in `docs/arbox-api/endpoints-reports.md`:
- **Endpoint**: `GET /v3/reports/entrance?from=YYYY-MM-DD&to=YYYY-MM-DD`
- **Auth**: `api-key` header (same as user endpoint, uses `ARBOX_API_KEY` env var)
- **Pagination**: `page` + `limit` params (max 500 per page)
- **Response**: `{ statusCode: 200, data: EntranceReportResource[], extra: [] }`

**EntranceReportResource fields** (from `docs/arbox-api/schemas-reports.md`):

| Field | Type |
|-------|------|
| `user_id` | integer or null |
| `name` | string |
| `email` | string or null |
| `phone` | string or null |
| `class_name` | string or null |
| `date` | string (date) |
| `start_time` | string (datetime) |
| `location_name` | string or null |

### New module: `src/lib/arbox/reports.ts`

- `fetchEntranceReport(from, to)` -- paginated fetch with same pattern as `fetchAllArboxUsers()` in `client.ts`
- Returns `EntranceReportEntry[]`

### New server action: `getTraineeAttendance(userId, fromDate, toDate)`

- Looks up `arbox_user_id` from trainee profile
- Fetches entrance report for date range
- Filters entries where `entry.user_id === profile.arbox_user_id`
- Returns `{ totalSessions, weeklyAverage, sessions: { date, className }[] }`
- Graceful fallback: if `arbox_user_id` is null or API fails, returns `null` (UI shows "N/A")

No caching for v1 -- on-demand fetch when report editor loads.

### Reused existing components

- `RatingTrendChart` -- overall + per-stat line trends
- `PhysicalMetricChart` -- individual metric trends (sprints, jumps, etc.)

- New dependency: `html-to-image` (preferred over `html2canvas` -- uses DOM-to-SVG, more accurate for SVG-based Recharts)

- `RadarStatsChart` added to `/admin/users/[userId]`
- Existing `AssessmentProgressCharts` reused on admin trainee view

## Report Editor Page

### Route

`/admin/reports/generate/[userId]` -- protected by `verifyAdminOrTrainer()`

### Sections

1. **Header bar** -- trainee name, avatar, "Generate PDF" button, date range picker (default: last 3 months)

2. **Details** (read-only) -- name, birthdate, position, club, registration date, weekly attendance (Arbox)

3. **Assessments** (read-only) -- comparison table of two most recent assessments, all physical metrics

4. **Charts** (read-only) -- radar chart (current stats), trend line charts (metrics over date range)

5. **Strengths** (editable) -- auto-populated from shift report `achievements` + `pro_candidates` notes in date range. Editable bullet list.

6. **Weaknesses** (editable) -- auto-populated from `limitations`, `injuries`, `discipline`, `mental_state` notes in date range. Editable bullet list.

7. **Social skills** (editable) -- auto-populated from new `social_skills` shift report notes in date range. Editable bullet list.

8. **Summary** (editable) -- textarea pre-filled with latest saved summary from `trainee_summaries`. "Save summary" button persists to DB.

### PDF generation

"Generate PDF" button: captures chart images, combines all sections with trainer edits, downloads via `@react-pdf/renderer` client-side.

## Edge Cases

**Zero assessments:**
- Assessments table: show "no assessments yet" message
- Radar chart: hidden (no data to display)
- Trend charts: hidden

**Single assessment:**
- Assessments table: show one column only (no comparison)
- Trend charts: show single data point (no trend line)

**No shift report notes in date range:**
- Strengths/weaknesses/social skills sections: show empty bullet list with placeholder text ("no notes for this period")
- Trainer can still add bullets manually in the editor

**No `arbox_user_id` linked or Arbox API failure:**
- Attendance field shows "N/A" in details section
- Non-blocking -- rest of the report generates normally

**Trainee with no age group peers (solo in age group):**
- Radar chart uses `calculateCardRatingsAbsolute()` fallback (absolute benchmarks) instead of percentile-based ratings
- Small note under radar chart: "based on absolute benchmarks"

**No saved summary:**
- Summary textarea shows empty with placeholder text

## New Dependencies

- `html-to-image` -- DOM-to-SVG chart snapshot capture (lightweight, ~10KB gzipped)

## Out of Scope (v1)

- Report caching / Arbox attendance caching
- Sharing via WhatsApp from the app
- Trainee-visible reports in dashboard
- AI-generated summary suggestions
- Batch report generation for multiple trainees
